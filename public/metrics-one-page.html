AIGC 互动大屏运营看板 · 指标说明

用于多台线下 AIGC 互动大屏的活动效果、生成稳定性与设备状态复盘。全部为固定种子的模拟数据， 观察截至 2026-08-30 20:00（北京时间），参与日期范围 2026-08-01 至 2026-08-30。
指标定义与计算口径为什么这样算运营可采取的行动
参与人数 所选范围内 participantId 去重数
（辅助：参与会话数 = 记录条数）		 人数是去重口径，跨日、跨点位重复参与只算一人；不能把各日或各点位人数相加。 判断活动整体吸引力与点位冷热。人数高但转化低，说明"看得多、拿得少"，问题在结果侧而非引流侧。
生成成功率 成功任务数 ÷ 已结束任务数
已结束 = 成功 + 失败 + 超时		 排队中与生成中不计入分母，否则会低估成功率；卡片单独列出这两个数量以免隐藏未完结工作。重试成功仍是一条任务，不放大分母。 下钻失败任务的错误码分布。超时集中 → 查上游排队与超时配置；模型报错集中 → 查服务可用性。低于 85% 建议立即介入。
扫码领取率 发生有效扫码的会话数
÷ 可领取会话数		 两者分母相同（可领取会话 = 生成成功 + 审核通过 + 已展示），但互不包含：用户可能直接分享而不扫码。合并成一个"转化率"会让其中一个异常被另一个的高值拉平而不可见。 生成与耗时均正常但领取率低 → 问题在现场：核查二维码可扫性、摆放位置与引导文案；必要时做 A/B。
分享转化率 发生有效分享的会话数
÷ 可领取会话数		 扫码正常而分享低 → 卡点在传播：核查分享入口、分享文案与可分享形式，而非结果质量。
平均生成时长
含 P90		 成功任务 (完成 − 提交) 的算术平均
P90：同批样本升序后
rank = (n−1) × 0.9 线性插值		 只看均值会漏掉长尾：生成时长是长尾分布，少数超时任务被大量正常样本稀释。因此异常判定用 P90 而非均值——P90 对尾部敏感、对样本占比不敏感。 均值平稳而 P90 抬升，说明是尾部恶化而非整体变慢，应查重试与排队；两者同时上升才考虑模型或网络整体退化。
内容审核 成功任务的 已通过 / 待审核 / 已拒绝
拒绝率 = 拒绝 ÷（通过 + 拒绝）		 拒绝率排除待审，否则未决项会稀释真实拒绝比例。待审时长从生成完成算到快照。 待审积压超过 10 分钟即影响现场体验——内容已生成但用户拿不到。核查审核队列是否停滞；拒绝率异常升高时排查诱导性输入并更新词库。
设备在线状态 心跳距快照 ≤120 秒为在线
>120 秒为离线；无心跳为未知		 快照口径，不随日期变化。未知（从未上报）与离线（已确认失联）必须分开，不能把未激活设备报成故障。 离线设备按点位联系现场核查网络与供电；离线期间的互动数据不代表投放效果，不应纳入效果评估。

统一口径备注

  • 归属口径：按会话开始时间的北京自然日归属。任务完成、审核与扫码/分享即使发生在所选日期之外，只要其会话开始于范围内且事件不晚于快照，就仍归属该批会话。不另设"事件发生日"统计模式。
  • 去重口径：参与人数按模拟匿名 ID 在整个所选范围重新去重；真实系统能否跨点位识别同一人，不在本原型中假定成立。
  • 汇总口径：总人数重新去重，总比率、均值与分位数均从合并原始样本重算——不能平均各点位的百分比，也不能平均各点位的分位数（分位数不是线性统计量）。
  • 零样本：零分母的比率、无成功样本的均值与 P90 一律显示 — 并标注"暂无样本"，不显示 0；真实观察到的计数值 0 仍显示 0。
  • 分位数算法：采用 NumPy 默认的 linear 方法。Excel、SQL 与 Python 的默认分位数算法不同，跨工具核对前须先统一口径。
  • 阈值性质：本页一切阈值（95% / 20% / 20 秒 / 10 分钟 / 120 秒）均为原型演示参数，不是生产 SLA 或行业基准，上线前须按实际业务定标。
