# 光影实验室 · AIGC 互动大屏运营看板

面向线下活动运营人员的中文后台原型，通过“运营总览”和“异常与明细”两个页面，查看参与、生成、领取、分享、审核及设备状态，并从异常回到对应任务或设备事件核对证据。界面采用 Vue 3、TypeScript、Element Plus 和 Apache ECharts；全部业务记录为固定种子的模拟数据。

本仓库为可运行的完整原型：模拟数据生成、领域计算、单元测试与双形态构建均已实际执行通过。环境为本机实测的 Node.js `24.19.0`、npm `11.17.0`，依赖版本由 `package-lock.json` 锁定。

## 查看与运行

最终交付提供两种查看方式：

| 产物 | 使用方式 |
| --- | --- |
| `deliverables/aigc-ops-dashboard.single.html` | 单文件构建的目标是直接双击打开；最终必须实际验证 `file://` 场景 |
| `deliverables/static-site.zip` | 解压后通过 HTTP 静态服务器访问，不能直接双击其中的 `index.html` 替代静态服务 |
| `deliverables/source.zip` | 解压后进入项目根目录，按下方命令安装、运行与重建 |
| `public/metrics-one-page.html` | 独立指标说明，可直接打开及打印；PDF 交付在导出后另行核验 |

开发或从源码运行：

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

在终端显示的本机地址打开页面。默认进入 `/#/overview`；异常与明细入口为 `/#/details?tab=anomalies`。两页共用日期和点位筛选，筛选及详情状态写入 URL，便于刷新恢复与回到同一证据范围。

预览常规生产构建：

```sh
npm run build
npm run preview -- --host 127.0.0.1
```

只用本地预览即可演示，不需要模型 API、账户、数据库或远程服务。当前没有已授权且验证的公开部署地址。

## 环境与命令

环境记录日期为 **2026-09-14**。Node.js `24.19.0` 和 npm `11.17.0` 为本次本机实测版本；是否已在这组版本下完成全部验证，应以测试报告为准。依赖的最终精确版本由 `package.json` 与 `package-lock.json` 固定，锁文件确定后补充实际版本记录，不以“最新版”代替。

| 命令 | 用途 |
| --- | --- |
| `npm ci` | 严格按锁文件安装，用于解压后的源码和干净副本检查 |
| `npm run dev` | 启动开发服务 |
| `npm run data:generate` | 生成固定模拟数据并更新 manifest，会写入正式数据目录 |
| `npm run data:validate` | 校验字段、关联关系、时间顺序、状态与数据规模 |
| `npm run data:verify` | 在项目内临时目录重复生成并比较文件字节与哈希 |
| `npm run lint` | 静态规则检查 |
| `npm run typecheck` | 独立 TypeScript / Vue 类型检查 |
| `npm run test:unit` | 单元测试，单次执行 |
| `npm run build` | 输出常规静态站点至 `dist/` |
| `npm run build:single` | 输出 `dist-single/index.html`，最终交付时复制至 `deliverables/` |
| `npm run preview` | 通过 HTTP 预览常规构建 |
| `npm run test:e2e` | 构建后运行浏览器关键路径，由测试配置管理预览服务 |
| `npm run verify` | 依次执行数据校验、复现、lint、类型检查、单测、常规构建；失败即停止 |

`verify` 不等于浏览器测试、单文件测试或打印验收。最终检查还需单独运行：

```sh
npm run verify
npm run test:e2e
npm run build:single
```

浏览器自动化需要项目所选 Playwright 版本对应的 Chromium。安装项目依赖后，可使用本地 CLI 准备浏览器：

```sh
npx --no-install playwright install chromium
```

下载需要可用网络与缓存写入权限；不要将下载失败写成测试通过。若改用可用的浏览器自动化工具完成等效检查，必须在测试报告中写清实际路径、未使用主路径的原因及未覆盖项。

PDF 需要支持中文系统字体的 Chromium 或等效打印浏览器。打开指标 HTML，选择 A4、100% 缩放、关闭浏览器页眉页脚，按 HTML 的 15 mm 页边距导出到 `deliverables/metrics-one-page.pdf`。导出后须核对页数为 1、文字无乱码、表格与页尾无裁切；本记录阶段尚未完成该核验。所有项目临时产物与日志放在项目内，不把字体文件打包给评审。

## 数据日期与指标口径

| 项目 | 固定演示设定 |
| --- | --- |
| 数据版本 / 种子 | `v1` / `aigc-ops-demo-v1` |
| 业务日期范围 | 2026-08-01 至 2026-08-30 |
| 观察截至时间 | `2026-08-30T20:00:00+08:00`，北京时间 |
| 默认范围 | 2026-08-24 至 2026-08-30，全部点位 |
| 目标规模 | 6 个虚构点位、12 台设备、6,000 个会话、4,500 个模拟匿名参与者；以最终数据校验为准 |

“最近 7 天”和“最近 30 天”相对于数据集结束日计算，独立于电脑当天日期。8 月 30 日仅观察到 20:00，不能与完整营业日直接视作相同观察长度。

- **参与与归属：** 按会话开始时间的北京时间自然日筛选。任务、审核、扫码和分享跟随该会话，跨日完成仍归回参与日，但所有观察均不得晚于固定快照。人数按模拟 `participantId` 在整个所选范围重新去重；真实系统能否跨点位识别人，不在原型中作出假设。
- **生成：** 成功率 = 成功任务数 ÷ 已结束任务数；结束状态包括成功、失败、超时，排队与生成中单独呈现。同一任务的重试不会新增任务分母。
- **领取与传播：** 可领取结果必须生成成功、审核通过且已展示。扫码领取率和分享转化率分别按有效事件关联的会话去重，都除以可领取会话数。重复事件只贡献一个会话；分享无需先扫码，两者是从可领取结果分出的并列分支。
- **耗时：** 均值与 P90 使用同一批成功任务的“提交至完成”时长，包含排队及重试等待，不含审核。P90 对排序样本按 `rank = (n − 1) × 0.9` 线性插值；多点位合并后重算，不平均各点位 P90。20 秒是原型演示告警阈值，不是生产 SLA。
- **审核：** 统计成功任务的通过、拒绝、待审数量；拒绝率排除待审。积压等待从生成完成时间算到快照。
- **设备：** 当前在线、离线、未知数量仅跟随点位。心跳距快照不超过 120 秒为在线，超过则离线，无心跳为未知。历史离线事件按离线区间与筛选日期是否相交展示。
- **空样本与汇总：** 计数保留真实的 0；零分母比例、无成功样本的均值与 P90 显示 `— / 暂无样本`。总人数重新去重，总比例、均值和分位数从合并原始样本重算。

详细定义见 [指标合同](docs/METRICS.md)、[数据结构](docs/DATA_SCHEMA.md) 及 [一页指标说明](public/metrics-one-page.html)。

## 工程结构与边界

```text
data/mock/v1/         唯一模拟数据源，构建时导入
scripts/             固定种子生成、校验与复现检查
src/domain/          独立于页面的日期、集合、指标与异常计算
src/data/            数据读取与索引
src/config/          固定演示日期及演示阈值
src/composables/      共享筛选与图表生命周期
src/pages/           运营总览、异常与明细
src/features/        趋势、转化、明细及抽屉
src/styles/          设计令牌与图表主题
tests/               独立小样本单测及浏览器关键路径
docs/                指标合同与数据结构规范
public/              一页指标说明（可打印 HTML 与 PDF）
deliverables/        构建产物副本：单文件 HTML、指标 PDF
```

这是运营后台原型；真实 AI 生成、硬件控制、审核服务、数据库、登录权限、真实分享链路、支付、导出及异常处理状态持久化均不在范围内。异常建议用于指引核查，不能据此认定真实根因。页面不提供未实现的重启、派单或重试任务操作。

源码保留源码、锁文件、模拟数据、生成与验证脚本、测试与文档；排除 `node_modules`、`.git`、构建缓存、临时检查目录、敏感环境文件及 `deliverables` 本身。静态包只包含最终 `dist/` 内容。最终修改文档或静态文件后，需要重建两种形态再打包，以免交付旧版本。
