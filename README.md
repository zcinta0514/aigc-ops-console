# AIGC 运营监控看板

**给 AI 生成类产品的运营监控后台 —— 一套经过实战推敲的指标口径 + 一个开箱即跑的参考实现。**

生成成功率的分母怎么定？耗时异常该看均值还是长尾？十几个点位的数据能不能加起来当全局？
这些问题没有标准答案，但**答错了会让故障从你眼皮底下溜走**。这个仓库把答案写成了代码，
并且用 72 条单元测试和 9 条端到端测试锁住。

## 它能做什么

### 运营复盘

- **七类核心指标**同屏呈现：参与人数、生成成功率、扫码领取率、分享转化率、平均生成时长（含 P90）、内容审核、设备在线状态
- **趋势对比**：均值与 P90 同轴绘制，两条线的间距就是长尾
- **六段会话漏斗**：参与 → 提交 → 成功 → 可领取 → 扫码 / 分享（后两段是并列分支，不是逐级收窄）
- **点位横向对比**：比率单元格内嵌归一化迷你条，谁好谁坏一眼扫出
- 日期区间与点位筛选**全部写入 URL**，刷新、前进后退、分享链接都能精确还原现场

### 实时监控

- **时间回放**：拖动时间轴或点播放，回放当天任意时刻。所有指标按那一刻**重算**——未开始的会话不出现、未完成的任务回到"生成中"、未出结果的审核不可见
- **逐小时趋势**：小时是当日在现场唯一有行动意义的粒度，按天看不出"下午三点开始变慢"
- **生成队列 / 待审队列**：正在发生的和卡住的内容，实时可见
- **设备网格**：在线 / 离线 / 未知三态，未知（从未上报）不冒充已确认离线

### 异常与追查

- **七类异常规则引擎**：成功率低、P90 耗时高、扫码低、分享低、审核积压、设备离线、设备未知
- **每条异常可下钻核对证据**：触发规则、实际值、阈值、分子分母、样本量、关联任务 ID 全部给出
- **证据链完整**：从异常 → 关联任务 → 所属会话 → 设备事件，一路点到底
- 异常清单可**导出 CSV** 离线核对；趋势图可**导出 PNG**

### 工程能力

- **双形态构建**：常规静态站点 + **单文件 HTML**（双击即开，无需服务器）
- **固定种子数据生成器**：重复生成逐字节一致，可自行验证
- **完整校验链**：`npm run verify` 一条命令跑完数据校验 → 复现校验 → lint → 类型检查 → 单测 → 构建

## 可以对接什么

领域计算层只认识一种输入形状 —— `Dataset`。**换成你自己的数据源，只需要实现一个 `DataSource` 接口，改 `repository.ts` 里的一行。**

```ts
// src/data/repository.ts
export const dataSource: DataSource = createFetchSource({
  baseUrl: '/api/dashboard',
  files: { tasks: 'generation-tasks', scans: 'qrcode-events' },  // 字段名不同就映射
})
```

仓库已内置两种实现（构建时内联静态数据、HTTP 接口），在此之上可以对接：

| 数据来源 | 做法 |
| --- | --- |
| **REST / GraphQL 接口** | 直接用 `createFetchSource`，补上鉴权与分页即可 |
| **WebSocket / SSE 实时流** | 实现一个推送式 `DataSource`。领域层已把「观察截止时刻」参数化，接上真实时只需让 `asOf` 跟随当前时间 |
| **消息队列（Kafka / Pulsar / RocketMQ）** | 经网关或 BFF 落成 `Dataset` 形状后接入 |
| **数据仓库（ClickHouse / Doris / Hive）** | 定时导出聚合结果，走静态数据源路径 |
| **Prometheus / OpenTelemetry** | 指标语义已用文档固化，映射到现有指标名即可 |
| **对象存储（OSS / S3）** | 把 `Dataset` 序列化后直传，前端拉取，适合纯静态部署 |

界面层与领域层**完全不需要改动**——它们只依赖 `Dataset` 这个契约。

## 适用场景

这套指标口径与交互模式，适用的不只是互动大屏：

### 线下 AI 互动设备
品牌门店、商场中庭、景区展馆里的 AIGC 互动屏、AI 写真机、AI 拍照打卡装置。
**典型痛点**：十几台设备散在各处，看不到哪台在掉线、哪台的内容没人要。

### AI 生成类产品
AI 绘画、图生视频、AI 头像、AI 试衣、AI 设计工具。
**典型痛点**：成功率、耗时、审核拦截三件事互相纠缠，用平均值把长尾故障盖住了。

### 内容审核团队
需要同时盯住「拦截率」和「积压量」的场景。
**典型痛点**：内容已经生成完了，但卡在审核队列里，用户当场拿不到——这个损失在业务指标上完全看不见。

### 线下智能设备运维
多台设备的在线状态 + 业务数据放在同一个视图里看。
**典型痛点**：IoT 平台只管设备心跳，业务看板只管数字，两边割裂，判断不了"设备离线期间的数据还算不算数"。

### AI 客服 / 机器人服务
把「生成成功率」「平均响应时长」「审核拦截」换成对应指标，交互模式可以直接复用。

### 作为模板直接改造
需要从零搭一个深色玻璃风格的数据看板时，设计令牌、ECharts 主题、图表生命周期封装、
筛选状态管理、导出能力都可以单独拿走用。

## 四个值得单独说的口径决定

这是本项目和"又一个看板模板"的区别所在。

### 1. 耗时异常按 P90 判定，不按平均值

生成时长是典型长尾分布，少数超时任务会被大量正常样本稀释掉。

仓库里植入了这样一个真实场景（长街光影馆 8-26）：当天**平均耗时约 9 秒，看起来完全正常；P90 却已达 35 秒**。
只看均值，这个故障永远不会被发现。

### 2. 扫码领取率与分享转化率分列，绝不合并

两者分母相同（可领取会话），但**互不包含**——用户可能直接分享而不扫码。

南岸艺术中心 8-28 就是专门构造的反例：当天扫码领取率 **44%** 正常，分享转化率仅 **3.7%**。
**如果合并成一个"转化率"，这个异常会被高值拉平，彻底消失。**

### 3. 排队中与生成中的任务不计入成功率分母

否则分母被未完结的工作撑大，成功率被系统性低估。
代价是这些任务会"消失"在指标里，所以成功率卡片**必须单独列出这两个数量**。

### 4. 分位数不能平均

分位数不是线性统计量。各点位的 P90 取平均，数学上没有意义。
所有汇总——人数、比率、均值、分位数——都必须**从合并后的原始样本重算**。

> 完整口径定义见 [`docs/METRICS.md`](docs/METRICS.md)，数据结构与约束见 [`docs/DATA_SCHEMA.md`](docs/DATA_SCHEMA.md)。

## 三个页面

| 页面 | 用途 |
| --- | --- |
| **运营总览** `#/overview` | 时间段复盘：指标卡、趋势、漏斗、点位对比、审核分布、设备状态、异常摘要 |
| **实时监控** `#/live` | 当日截面：时间回放、逐小时趋势、生成队列、待审队列、设备网格 |
| **异常与明细** `#/details` | 证据核对：异常、生成记录、审核记录、设备快照与历史离线事件，均可下钻 |

### 时间回放

![时间回放](docs/images/replay.png)

回放不是"把当前数字换个时间标签"——领域层会把每条记录**还原成它在那一刻的样子**。

回放中最后一段是"进行中"的小时，图上会明确标出，避免把"这个小时还没走完"误读成"参与人数骤降"。

### 异常可下钻核对证据

![异常与明细](docs/images/anomalies.png)

每条异常都由原始记录按规则推导，**不存在硬编码的假告警**。
异常详情给出规则、实际值、阈值、分子分母、样本量与关联任务，并明确声明"规则输出不等于已确认根因"。

## 项目结构

```text
data/mock/v1/         模拟数据，构建时内联
scripts/generator/    固定种子生成器（含受控异常配额）
src/domain/           时间、会话集合、指标、分位数、设备状态、异常推导
src/data/             数据源抽象与实现
src/config/           品牌、演示日期、异常阈值
src/composables/      筛选状态、图表生命周期、导出
src/features/         页面区块与抽屉
src/pages/            三个页面
src/styles/           设计令牌、全局样式、ECharts 主题
tests/                单元测试与端到端测试
docs/                 指标合同与数据结构规范
```

**分层原则**：`src/domain/` 是纯 TypeScript，不依赖 Vue、DOM、路由或图表库。
所有指标计算都可以脱离界面单独测试——这也是 72 条单测能存在的前提。

**配置化**：改品牌名与导航只看 [`src/config/brand.ts`](src/config/brand.ts)；
演示日期在 [`src/config/demo.ts`](src/config/demo.ts)；异常阈值集中在 [`src/config/thresholds.ts`](src/config/thresholds.ts)。

## 模拟数据是怎么造的

数据不是随机生成的，是**按配额构造**的：

- 固定种子 `aigc-ops-demo-v1`，重复生成**逐字节一致**（`npm run data:verify` 可自行验证）
- 6 个点位、12 台设备、6,000 条会话、4,500 个去重参与者，数量精确
- 植入了 **5 个受控异常场景**，生成器**逐条断言必须命中**，不靠换种子碰运气
- `npm run data:validate` 会逐条校验外键完整性、时间顺序、离线区间不重叠、非成功任务不得出现审核结论等约束

**每一个异常场景都能在界面上找到，并下钻到具体任务核对。**

## 测试

```bash
npm run test:unit    # 72 条
npm run test:e2e     # 9 条
```

单元测试覆盖的是最容易出错、也最难在界面上看出来的地方：

- 去重（跨日跨点位同一人只算一人）
- 跨日归属（任务在次日完成，仍归属会话开始那天）
- 合并汇总（**不能平均各点位的百分比**）
- 分位数（**不能平均各点位的 P90**，插值口径与 NumPy 对齐）
- 零分母（显示 `—` 而不是 `0`，不产生 NaN）
- 异常阈值边界（恰好等于阈值不触发；样本量不足不告警）
- 设备在线判定的 119 / 120 / 121 秒边界

**所有期望值都是独立手算后写死的，没有一条通过调用被测函数反算得到。**

端到端测试覆盖三个页面的关键路径，并**断言控制台错误为空**——页面静默报错时测试应当失败，而不是只截个图了事。

## 已知限制

写在这里不是谦虚，是免得你踩坑：

- **数据是固定快照，不是实时流。** 观察截至 2026-08-30 20:00，页面上已明确标注。回放是对既有事件的重演，不是模拟新数据。
- **不接入真实 AI 生成、审核服务或设备控制。** 页面上不出现"重启设备""重新派单"这类点了没用的按钮。
- **阈值均为演示参数**（95% / 20% / 20 秒 / 10 分钟 / 120 秒），不是生产 SLA，上线前需按实际业务定标。
- **设备状态只有最后一次心跳**，没有心跳历史，因此该面板固定为快照口径，不参与时间回放。
- 参与者去重依赖模拟匿名 ID。真实系统能否跨点位识别同一人，本原型不作假设。
